# Technical Drawing Reference and Evidence Rules

Keep evidence class explicit. A reference can inform only the kinds of conclusions permitted by its class.

## Evidence classes

### APPROVED VISUAL REFERENCE

Human-approved visual guidance may define appearance, dimension placement, opening-symbol presentation, drawing hierarchy, and visual conventions. It does **not** automatically establish physical/product facts, profile dimensions, construction rules, or catalogue compatibility.

### APPROVED SEMANTIC REFERENCE

An explicit human-approved meaning may define semantics such as “this region is a window,” “this region is a door,” “this symbol denotes an opening mode,” or “this is a combined door + window composition.” Do not extend that meaning beyond what was explicitly approved.

### CATALOGUE VERIFIED

Use only for facts explicitly checked against authoritative catalogue evidence. Record the exact source and scope. A visual sketch, approximate reference, label, or internet drawing alone does not establish this class.

### EXAMPLE ONLY

Example measurements, proportions, and numeric labels illustrate a drawing or interaction only. They are not defaults, constraints, dimensions, or production values.

### UNKNOWN

Unsupported or ambiguous information remains UNKNOWN. Do not fill gaps by convention, resemblance, string matching, or assumption.

## Conclusion labels

For reviews, use the task’s evidence labels: VERIFIED, HUMAN-APPROVED VISUAL RULE, HUMAN-APPROVED SEMANTIC RULE, LIKELY, ASSUMED, UNKNOWN. These describe the support for a conclusion; they do not upgrade a reference’s permitted scope.

Only VERIFIED or explicitly HUMAN-APPROVED rules may drive implementation, and then only within scope. LIKELY, ASSUMED, and UNKNOWN conclusions must not become production geometry or catalogue facts.
